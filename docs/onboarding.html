You'll see the hero with a slowly drifting Ursa Major constellation over a warm aurora. Scroll down and the constellation smoothly reshapes into Orion (Experience), Leo (About), Corona Borealis (Certifications), then Cygnus (Contact). Keep scrolling past Contact and you'll land right back at Home — that's the loop.

# run the unit tests (Jasmine + Karma, opens Chrome)

02.1The Big Idea

The night sky isn't decoration — it is the navigation. The entire site is one continuous, downward-looping scroll through five sections: Home, Experience (Work), About, Certifications, and Contact. Each section owns a real constellation; scrolling between them morphs one figure into the next, and passing the end wraps you back to the start without any visible jump.

  • No router. The "pages" under src/app/pages/ are full-viewport <section>s stacked in one template. You navigate by scrolling (or clicking a nav link), not by changing routes.
  • Experience over efficiency. The design rewards visitors who scroll through the journey. Motion is restrained — opacity, blur, long easing curves — never flashy for its own sake.
  • Accessibility from the start. The nav works with keyboard and screen readers, the loop clone is inert, and every animation respects prefers-reduced-motion.

02.3The Scroll Loop

A few terms first (all defined in CONTEXT.md):

Cycle

One full pass through Home → Work → About → Certifications → Contact. Measured in "destination units" where 0 = Home, 1 = Work, and so on.

Loop clone

A hidden, non-interactive copy of Home placed right after Contact. It gives the last section something to scroll into, and makes the wrap-back look seamless.

Seam

The wrap point. When you scroll into the clone, the screen looks identical to real Home — so jumping back is invisible.

One-direction

The loop only wraps going down. Scrolling up works normally and stops at Home. Two-way looping was considered but fights the browser's native scroll.

Try it — drag the slider to scroll through the sections. When you reach the end, the page wraps back to Home without any visible jump.

This demo uses simplified numbers — each section is 700 px tall, making the full cycle 3500 px. When you cross the end, it runs scrollTo(scrollY − 3500). Any leftover scroll momentum is preserved, so you never feel a stutter. Dragging left just clamps at Home because the loop only wraps in one direction.

How it works, step by step:

  1. AppComponent measures each section's position on the page (and re-measures whenever the layout changes). It passes those positions to ScrollLoopService.setAnchors(). The last anchor — the clone — tells the service how long one cycle is in pixels.
  2. On every scroll event the shell asks loop.wrapOffset(scrollY) whether a wrap is due. If it is, the shell calls window.scrollTo() to jump back, preserving any leftover momentum so it never feels like a hard stop.
  3. The shell also updates loop.update(scrollY, innerHeight), which recalculates the continuous position signal using pure functions from scroll-loop.math.ts.
Three clear responsibilities The app shell handles all DOM reads and writes. ScrollLoopService manages the state. scroll-loop.math.ts handles the arithmetic and is fully unit-tested. When adding new code, keep it on the right side of these lines (see ADR-0007).

02.4Staying Smooth at 60 fps

All animations share one requestAnimationFrame loop — FramePulseService — running outside Angular's zone. The constellation morph and nav fade both write directly to the DOM from that loop. Two rules keep Angular's change detection out of the way:

  • position is the fast signal — never bind it in a template. It's read ~60 times a second from animation callbacks. Binding it in a template would force Angular to re-check the whole component tree on every frame.
  • activeDestination is the template-safe signal. It only changes when you cross from one section to the next (not on every pixel of scroll), so it's fine for the nav underline and aria-current.

FramePulseService.onTick(fn) returns an unsubscribe function. The loop starts when the first subscriber joins and stops when the last one leaves. It pauses on hidden tabs and resets its clock cleanly on return.

The shell follows the same pattern: AppComponent uses OnPush, and its scroll/resize listeners run outside Angular's zone. The ResizeObserver batches reflows into a single requestAnimationFrame so things like lazy images and the showcase re-measuring trigger one measurement, not a cascade.

02.5How Theming Works

Every colour in src/styles.css is declared once using light-dark(light, dark). The browser picks which value to use based on color-scheme:

  • By default, color-scheme: light dark follows whatever the operating system prefers.
  • When the user toggles the theme, ThemeService adds a .light-mode or .dark-mode class that flips the scheme. No token overrides needed, with one small exception (--scrim-rgb, which can't use light-dark() because it's a raw RGB triple).
  • The aurora's appearance is a theme decision too — aurora-palette.ts maps each theme to a different set of shader colours and intensity.

03.2Navigation — No Router

There's no RouterModule — the five "pages" are sections of one template, and you navigate by scrolling:

  1. One registry drives everything. destinations.ts exports an ordered array of sections. The nav links and constellation shapes both derive from it, so they can't fall out of sync.
  2. The shell template lays out the sections in app.component.html: five <section>s stacked in scroll order, plus the hidden Home clone at the end. Home is always visible (it's the first thing visitors see); the other sections fade in as you reach them.
  3. Clicking a nav link scrolls you there. Short hops use smooth scrolling. Long jumps teleport instantly using startViewTransition(), styled as a directional drift-fade.
  4. Two deliberate exceptions (documented in destinations.ts): the #projects sub-anchor inside Work, and the desktop nav omitting Home because the logo already takes you there.
  5. Deep links work because Netlify's catch-all redirect serves the app for any URL.

04.1Add a New Project

Two steps, no template changes — the Work page renders whatever is in PROJECTS.

  1. Add a screenshot to src/assets/ as WebP (the project's standard image format — typically ~90% smaller than PNG). If the screenshot looks different in dark and light mode, provide both versions; otherwise reuse the same path for both.
  2. Append an entry to PROJECTS in src/app/pages/work/work-data.ts:
// src/app/pages/work/work-data.ts — append inside PROJECTS
{
  title: 'My New Project',
  description:
    'One to three sentences. What it is, the stack, and what it proves. ' +
    'Written for a hiring reviewer.',
  tech: ['Angular', 'TypeScript', 'Spring Boot'],
  href: 'https://github.com/Robotbino/my-new-project',
  demoHref: 'https://my-new-project.netlify.app/', // optional — renders a "Live Demo" link
  img: {
    dark:   '/assets/my-project.webp',  // shown in dark mode
    light:  '/assets/my-project.webp', // shown in light mode
    width:  1920,             // intrinsic px — REQUIRED; rendered as the <img> width/height
    height: 1080,             //   so the browser reserves the box before the lazy image lands
    alt: {
      dark:  'My New Project dashboard in dark mode',
      light: 'My New Project dashboard in light mode',
    },
  },
},
Dimensions are required TypeScript enforces width and height (in pixels) — the project won't build without them. If your dark and light screenshots differ slightly, just use the dark one's dimensions. The card uses object-fit: cover, so small ratio differences won't show.

Skills copy works the same way — edit EXPERIENCE_GROUPS in the same file.

04.2Update Your Certifications

Real credentials only Titles, issuers, and verify URLs must match actual, verified certificates — don't embellish or add entries that aren't genuine. The img and alt fields are for the visual preview only.
// src/app/pages/certifications/certifications-data.ts — append inside CERTIFICATIONS
{
  title:  'Exact Certificate Title',
  issuer: 'Issuing Organisation',
  href:   'https://verify.example.com/…',  // the official verify URL
  img:    '/assets/certs/my-cert.webp',    // scan for the spotlight — WebP, in src/assets/certs/
  alt:    'Exact Certificate Title certificate from Issuer',
},

The scan is the largest asset a certificate adds, so convert it to WebP before committing (a screenshot at q82 drops from ~1.3 MB to ~50 kB with no visible loss). On a fine pointer the spotlight FLIP-morphs from a cursor-tethered preview; on touch that preview never mounts, so tapping the row opens the spotlight directly.

04.3Tweak the Constellation

All star data lives in src/app/constellation/constellation.figures.ts. The one rule: every figure must have exactly 8 stars, because the morph animation pairs them by index. Tests enforce this — run npm test after any edit.

Move or reshape a figure

Each figure is a list of [x, y] coordinates in a 300 × 300 viewBox, plus its own line list:

// constellation.figures.ts — e.g. the Work figure (Orion)
work: figure('Orion', [
  [96, 96],    // star 0 — Betelgeuse   ← move a star by editing its [x, y]
  [176, 84],   // star 1 — Bellatrix
  // … exactly 8 coordinate pairs, always
], [
  { a: 2, b: 0 },  // a line between stars 2 and 0 (indices into the array above)
  { a: 3, b: 4 },  // link counts MAY differ per figure — lines cross-fade at the
]),                //   dim point of each morph, so they never need to match up

Change star character (size & drift)

Per-index traits are shared across all figures so star i keeps its identity through every morph:

// shared per-index traits — index i applies to star i of EVERY figure
export const R   = [3.3, 2.6, 2.2, 2.5, 2.7, 2.7, 2.6, 2.6]; // star radius
export const AMP = [6, 5, 5, 6, 6, 6, 7, 7];       // drift radius (viewBox units)
export const PHX = [0.0, 0.8, 1.6, 2.4, 3.2, 4.0, 4.8, 5.6]; // x-drift phase
export const PHY = [1.0, 2.2, 0.4, 1.7, 2.6, 0.9, 1.5, 3.0]; // y-drift phase
  • Bigger stars: raise values in R. Lazier/livelier drift: adjust AMP; phases (PHX/PHY) just de-synchronise the wander.
  • Morph behaviour (timing, dim point, interpolation) lives in constellation-morph.ts / morph-driver.ts — both spec-covered.
  • Reduced motion: the drift and morph settle automatically via MotionSettingsService; you don't need to handle it per figure.

04.4Tune the Aurora

The WebGL aurora's appearance is a theme decision, so its controls live in src/app/core/aurora-palette.ts — not in the shader or the shell template:

// src/app/core/aurora-palette.ts
export function auroraPalette(isDark: boolean): AuroraPalette {
  return isDark
    ? { colorStops: ['#1E1C1A', '#3D312A', '#5A3D2B'], blend: 0.5, amplitude: 1.0, speed: 0.5, lift: 0 }
    : { colorStops: ['#FBEAD9', '#F3D3AE', '#E8BC8C'], blend: 1.0, amplitude: 0.6, speed: 0.5, lift: 1 };
}
KnobWhat it controls
colorStopsThree-stop gradient the simplex noise flows through (left → right). Light mode is a warm dawn ramp — cream → peach → amber — deepening rightward into the hero's negative space
blendHow softly the aurora blends into the page background (higher = softer)
amplitudeVertical intensity of the waves — light mode stays calmer (0.6) than dark (1.0)
speedFlow speed of the noise field
lift0 = the ramp is scaled by intensity (dark: colour darkens toward the edges); 1 = the ramp tints at full value so light mode's warm stops actually paint instead of resolving to a grey wash. Without lift, a near-white light ramp renders as neutral grey

The shader itself (GLSL simplex noise via OGL) is in src/app/aurora/aurora.component.ts. Change it only if the palette knobs above can't do what you need. If you do, make sure two alternate paths still work: the CSS gradient fallback (when WebGL isn't available) and the reduced-motion path (a single static frame). Both are covered by aurora.component.spec.ts — run npm test after editing.

04.5Typography — Three Faces, Three Roles

The type system runs three faces, and each one has exactly one job. They used to blur: --font-family and --font-family-display both resolved to Nohemi, so the system had three token names but only two voices — which is why hero metadata read as generic UI chrome. Nohemi is a geometric display sans (circular bowls, tight apertures) and small uppercase runs are precisely where that face gives up.

TokenFaceJob
--font-family-displayNohemi — self-hosted .woff2Display only. h1–h6, the hero eyebrow and statement lead, the logo, mobile nav links, poster numerals.
--font-familyAtkinson Hyperlegible — Google FontsUtility / body. Everything else: body copy, metadata, labels, nav, controls.
--font-family-accentInstrument Serif — Google FontsAccent. A word or two of italic serif. Never a whole heading.
  • Anything at display scale must say --font-family-display out loud unless it's an h1–h6 (the global heading rule in styles.css covers those). The one non-heading exception, .hero-eyebrow, declares it in landingpage.component.css.
  • Atkinson ships 400 and 700 only. CSS font matching resolves the in-between tokens deterministically — --font-weight-medium (500) renders 400, --font-weight-semibold (600) renders 700. No synthetic weights are made. Hero utility rules state 400/700 outright rather than asking for a face that isn't there; everything else snaps, which is stable and fine.
  • The Nohemi ladder is untouched by that — it still carries all eight weights (100–700, 900) and remains the contrast engine for display type.
  • One Google Fonts request, not two. css2?family=Atkinson…&family=Instrument… costs a single round trip on the connection the preconnects already opened. If you add a face, extend that URL — don't add a second <link>.
  • Only two Nohemi weights are preloaded (ExtraLight and Black — what the hero paints first). The preload hrefs must match the @font-face src in styles.css byte for byte, or the browser fetches a second copy and warns the preload went unused. Both sides are root-absolute for that reason.

Hero clearance — the rule behind the sizes

The constellation is viewport-centred (top:50% left:50%, a square clamp(280px, 42vw, 520px)), so it runs straight through the middle of the hero frame — roughly x 460–980 on a 1440px viewport. It is the design, not a backdrop. The hero therefore holds three lines it must not cross:

  • The headline stays left-anchored and does not grow. "Hlongwana" at Black 900 measures ~5.2em; at the 7.5rem cap that's ~624px from the gutter, which is tuned. At 10rem it would be ~832px and run through the figure.
  • The statement keeps a tight measure (42ch) so the right-hand negative space stays open. It tightened from 46ch purely to offset Atkinson's wider ch.
  • The ::before scrim stays as it is — widening it hides more of the constellation.
Buy presence with contrast, never with width Display dominance on this site comes from making the small rungs smaller and distributing vertically — not from growing type rightward. The hero eyebrow shrank to widen the headline:eyebrow ratio from 1.88 to 2.50, and .hero-frame uses space-between so meta pins to the top, the headline owns the middle, and the footer anchors the base. The full clearance note sits at the top of landingpage.component.css — read it before changing any size there.

04.6Update Design Tokens

Plain CSS, not SCSS All tokens are CSS custom properties in src/styles.css under :root. That covers the type scale, font weights, colours, spacing, radii, shadows, easings, and layout widths.

The one theming rule: declare each colour once using light-dark(), never as separate light/dark overrides:

/* src/styles.css — the pattern for every colour token */
:root {
  color-scheme: light dark;                /* follows the OS with no class */
  --color-background:  light-dark(#ffffff, #121212);
  --color-accent-vivid: light-dark(#d9480f, #ff8c42);  /* the ONE non-monochrome hue */
  --ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);      /* the house easing curve */
}
.light-mode { color-scheme: light; }       /* manual toggle only flips the scheme */
.dark-mode  { color-scheme: dark; --scrim-rgb: 18, 18, 18; }
  • Never hardcode hex values in component CSS. Always add a token in styles.css and reference it — otherwise one of the two themes breaks.
  • Don't add overrides to .light-mode/.dark-mode — those classes only flip color-scheme (plus --scrim-rgb, the one documented exception).
  • Use the house easing. New animations should use --ease-out-expo / --transition-slow — long and calm is the pattern here.
  • Some rungs are fluid, most step. --font-size-5xl and --font-size-display-sm are clamp()s and must not get a @media override — that's what replaced their old breakpoint step. --font-size-6xl and --font-size-4xl stay stepped on purpose: a fluid rewrite was drafted and reverted because measurement showed the section titles aren't near overflow above 768px (Certifications inks 605px into 705px available), so smoothing the cliff would have cost 37% off four titles for a jump only visible while dragging a window.
  • --section-spacing is no longer var(--space-5xl) — it's clamp(var(--space-2xl), 8vh, var(--space-5xl)). That decoupling is deliberate: .section is used by all four content sections, so raising that spacing rung for one thing used to silently inflate every one of them.
  • There is no --space-6xl. It was deleted — zero consumers, and its mobile override was smaller than --space-3xl, so anything that started using it would have shrunk on phones. Don't reintroduce it; --space-4xl/--space-5xl were widened to cover the range.
  • --font-size-2xs (11px) exists to tokenise what used to be a one-off literal. Reach for it before hardcoding a small size.
  • The weight ladder belongs to Nohemi, the display face — --font-weight-thin (100) through --font-weight-black (900). There's no weight 800 token — it had no use and was dropped. Re-add the token and its @font-face together if a future design needs it. Applied to body/utility text the ladder collapses, because Atkinson ships 400/700 only; see 04.5 Typography.

04.7Add a Whole New Section

This is less common, but here's the full checklist. The registry keeps the nav and constellation in sync automatically — you only need to touch the shell template and the module by hand.

  1. src/app/destinations.ts — extend the DestinationFigure union and add the entry at its scroll position (order = array position): 
    export type DestinationFigure = 'home' | 'work' | 'about' | 'certifications' | 'contact' | 'lab';

{ id: 'dest-lab', label: 'Lab', figure: 'lab' },
  2. constellation.figures.ts — add a lab: figure to byRoute with exactly 8 stars (the destinations.spec.ts guard fails the build-time tests if the key doesn't resolve).
  3. app.component.html — add the section in scroll order, before the Home clone (the clone must stay last — it is the seam): 
    <section #dest id="dest-lab" class="dest"><app-lab></app-lab></section>
  4. Create the component under src/app/pages/lab/ and declare it in app.module.ts. Write the section header inline in the editorial pattern every other section uses — a kicker (aria-hidden destination numeral + a short hairline rule) above a poster title in the Nohemi weight ladder; copy the markup from about.component.html and give it the next index (06). Put the section's copy in a lab-data.ts, matching the house pattern.
  5. Verify: npm test (registry + figure guards), then scroll a full loop in the browser — check the new morph both in and out, the nav underline, and the seam still wrapping invisibly.
Leave the clone alone The last <section> is a hidden copy of Home. It must stay last and look exactly like the real Home — the seamless loop depends on it being pixel-identical. See ADR-0004 for the reasoning.
